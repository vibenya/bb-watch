# Реализация BB Watch: статус относительно A01–A30

> The Home list described in older rows was replaced on 2026-10-16 by a three-page UI (Record, Stage, Threads); see the [handoff](../docs/HANDOFF.md). Criterion statuses below were not re-evaluated against it.
>
> Historical baseline: later installation and user recording/send confirmation are recorded in [current handoff](../docs/HANDOFF.md) and [validation](VALIDATION.md). Earlier device-blocked statements below are superseded; remaining acceptance gaps still apply.

Это первый интеграционный срез: watch-only приложение, запись на часах, подключение к BB, доставка текста и простой single-choice ответ. Таблица сверена с исходниками и матрицей в `specs/bb-watch-product-spec.md`. Девять SwiftPM тестов, обе исполняемые проверки, строгая Swift 6 проверка для watchsimulator и сборки двух SDK прошли. Watch-only приложение также запущено в watchOS 26.1 симуляторе. Это не подтверждает запись звука, LTE или другие сценарии на физических часах.

| Критерий | Статус | Что есть или чего не хватает |
|---|---|---|
| A01 | Не проверено | Watch-only target и локальная запись без аккаунта есть; pairing и полный запуск без iPhone не проверены на часах. |
| A02 | Не проверено | AVAudioEngine, запрос разрешения микрофона и таймер реализованы; фактический захват и время старта требуют Ultra 2. |
| A03 | Не проверено | Пауза, продолжение и явная отправка реализованы; непрерывность аудио и управление на часах не проверены. |
| A04 | Не проверено | Можно выбрать загруженный тред; доставка именно туда требует интеграционной проверки. |
| A05 | Отсутствует | Новый тред создаётся одним запросом, но после потерянного ответа запрос статуса/идемпотентное восстановление не поддержаны; исход остаётся неопределённым и повтор заблокирован. |
| A06 | Частично | Запись из треда адресуется этому треду. Голос из Needs You отправляется как уточнение в тред и не привязан к версии вопроса. |
| A07 | Не проверено | Аудио пишется небольшими файлами с периодическими checkpoint без остановки микрофона; часовой прогон, RAM, стыки и фон не проверены. |
| A08 | Частично | `NWPathMonitor` и обновление BB запускают очередь для записей, не дошедших до необратимого запроса. Если исход мутации неизвестен, повтор блокируется во избежание дубля; сверка и возобновление той же отправки пока не реализованы. Сетевой сценарий не проверен на часах. |
| A09 | Не проверено | Черновики и файлы восстанавливаются при запуске; окно потери до двух секунд и восстановление после force-quit/разряда не измерены. Неопределённая доставка требует ручной сверки. |
| A10 | Не проверено | Прерывание аудиосессии останавливает запись и сохраняет завершённые части; звонки и смена маршрута проверяются на устройстве. |
| A11 | Не проверено | Перед созданием аудиофайла проверяется резерв 20 MB и ошибка записи останавливает захват; поведение при исчерпании места и сохранность предыдущих файлов не проверены. |
| A12 | Отсутствует | Неудачный чанк сохраняет оригинал и ошибку всей отправки, но в интерфейсе нет локализации проблемного чанка. |
| A13 | Частично | Повторные действия блокируются локально во время отправки и при неизвестном результате; backend idempotency key не используется, дубль на сервере не исключён контрактом. |
| A14 | Не проверено | Для одного адресата используется порядок по времени постановки в очередь; гонка двух отправок и восстановление порядка не проверены. |
| A15 | Частично | Треды и загруженные сообщения кешируются для чтения offline; текст озвучивается системным русским AVSpeechSynthesizer. Нет отдельной загрузки/кеша аудио BB, состояния генерации и повторной загрузки. |
| A16 | Отсутствует | Краткое изложение и переключение кратко/полностью не реализованы; доступен полный текст. |
| A17 | Не проверено | Воспроизведение ставится на паузу при системном прерывании или отключении текущего аудиомаршрута; поведение на часах/наушниках не проверено. |
| A18 | Не проверено | Single-choice варианты показываются целиком системными кнопками; проверки длинных вариантов, прокрутки и размера касания не проведены. |
| A19 | Не проверено | Для поддержанного single-choice создаётся отменяемое намерение на 10 секунд; положение кнопки и Dynamic Type максимального размера не проверены. |
| A20 | Не проверено | Срок и намерение сохраняются на диск. Возобновление после закрытия/приостановки и отсутствие дублей требуют проверки; таймер сам по себе не гарантирует работу в фоне. |
| A21 | Есть в коде | Пока намерение остаётся в статусе ожидания, его можно отменить; сетевой сбой при проверке вопроса оставляет его ожидающим. Офлайн-сценарий не прогонялся. |
| A22 | Не проверено | Перед разрешением повторно загружается актуальный вопрос, но гонка с другим устройством и атомарность на сервере не проверены. |
| A23 | Частично | UI явно предупреждает, что голос — уточнение, а не выбор варианта. Ответ голосом на конкретный interaction не реализован. |
| A24 | Отсутствует | Multi-select и группа обязательных вопросов явно считаются неподдерживаемыми. |
| A25 | Отсутствует | Single-choice перед commit сверяет fingerprint вопроса; для голосовой записи версия вопроса не сохраняется, поэтому сценарий во время диктовки не закрыт. |
| A26 | Частично | Основные списки и загруженные сообщения кешируются, их можно обновить вручную. Push, курсор событий, replay и дедупликация входящих событий не реализованы. |
| A27 | Не проверено | Credential хранится в Keychain, черновики привязаны к идентичности подключения и не отправляются другому аккаунту; истечение токена и переключение аккаунтов не проверены. |
| A28 | Не проверено | Используются стандартные SwiftUI элементы, но VoiceOver, Dynamic Type, Reduce Motion и Reduce Transparency не проверялись. |
| A29 | Не проверено | Target независим от iPhone-приложения; LTE, Wi-Fi и полный поток с выключенным/недоступным iPhone ещё не проверялись. |
| A30 | Отсутствует | Показывается подтверждение «Принято BB»/«В очереди», но фактическое состояние занятого или остановленного агента не загружается. |

## Сборка и запуск

Сгенерированный Xcode-проект находится в `native/BBWatch.xcodeproj`. Плановая команда для unsigned generic build:

```sh
xcodebuild -project native/BBWatch.xcodeproj \
  -scheme BBWatch \
  -destination 'generic/platform=watchOS' \
  CODE_SIGNING_ALLOWED=NO build
```

Последний `./native/check.sh` прошёл: девять SwiftPM тестов, URLSession контрактный исполняемый тест, аудио checkpoint исполняемый тест, строгая Swift 6 typecheck для watchsimulator и unsigned-сборка watchOS и ad-hoc-подписанная сборка watchsimulator SDK. Watch-only приложение установлено и запущено в симуляторе watchOS 26.1. Предыдущий build через generic destination остановился до компиляции: Xcode сообщил, что компонент watchOS 26.1 отсутствует, хотя SDK установлен. Прямая SDK-сборка проходит.

Ultra 2 на watchOS 26.6 доступна как paired device; Developer Mode выключен, а попытка физической установки завершилась timeout. После включения Developer Mode потребуется успешная установка с подходящей подписью и provisioning profile; выберите часы как destination в Xcode. Подключение к BB выполняется в приложении часов: BB → Settings → Mobile → Add mobile device; введите одноразовый код в BB Watch → Connect BB. Затем отдельно проверяются чистый запуск, разрешение микрофона, LTE/Wi-Fi при недоступном iPhone, запись, отправка, ответ и восстановление.

Simulator runtime установлен. Сборка для устройства успешно подписана существующим Apple Development сертификатом; ожидаются включение Developer Mode и доступность соединения с Ultra 2. Физическая установка и поведение приложения на часах не проверены. Полные команды сборки/симулятора приведены в `native/VALIDATION.md`.
